## 1. Visão Geral da Comunidade de Leitura

O pilar comunitário do DIYSpur conecta leitores em torno de livros específicos e interesses comuns. Cada clube funciona como um espaço de diálogo organizado em múltiplos **Canais de Discussão** com controle estrito de acesso, tolerância a falhas de rede e proteção ativa contra spoilers.

```mermaid

    BOOK["Livro no Catálogo (/livros/[slug])"] -->|Gatilho Automático na Criação| OBG["Clube Oficial do Livro (official_book_groups)"]

    CONSENT -->|Sim| SPOIL_MODAL["Termo de Consentimento de Spoiler<br/>(channel_members_spoiler_consent)"]
    CONSENT -->|Não| CHAT["Workspace de Chat em Tempo Real"]
    SPOIL_MODAL -->|Confirmado pelo Leitor| CHAT
```

## 2. Tipologia de Clubes e Grupos Oficiais

### 2.1 Clubes Oficiais do Livro (`official_book_groups`)
- Quando uma obra é publicada no catálogo (`books`), o banco de dados assegura a existência de um **Clube Oficial** correspondente através do trigger de catálogo ou migração de alinhamento.
- **Invariantes Arquiteturais (DB01, DB02, DB15):**
  - Todo livro possui exatamente um clube oficial com slug canônico derivado (ex.: `clube-verity`).
  - O grupo oficial não pode ser deletado acidentalmente por usuários comuns.
  - O grupo nasce com 3 canais estruturados: `#geral`, `#spoilers` e `#duvidas`.
  - Novos capítulos adicionados à obra geram canais automáticos correspondentes quando configurado.

### 2.2 Clubes Comunitários Criados por Usuários (`user_clubs`)
- Qualquer leitor autenticado pode criar um clube independente (`/clubes/novo`).
- **Modalidades de Acesso:**
  - **Público (`is_private = false`):** Qualquer leitor pode visualizar a listagem, explorar o diretório de canais e participar das discussões.
  - **Privado (`is_private = true`):** Visível apenas para o proprietário (`owner`) e membros com convites aceitos (`status = 'accepted'`). Não membros recebem 404/403.
- **Papéis no Clube (`club_members.role`):**
  - `owner`: Criador do clube, com poderes totais de configuração, banimento e agendamento de eventos.
  - `moderator`: Membro com poderes delegados para apagar mensagens inadequadas e criar canais.
  - `member`: Participante com direito a envio de mensagens e reações.

## 3. Arquitetura de Canais (`club_channels`)

Cada canal possui metadados específicos para orientar o comportamento da interface:

| Campo | Tipo | Descrição & Regra de Comportamento |
|---|---|---|
| `id` | `uuid` | Identificador único do canal (PK). |
| `club_id` | `uuid` | Chave estrangeira referenciando `user_clubs(id)`. |
| `name` | `text` | Nome legível do canal (ex.: "geral", "spoilers-finais", "capitulo-01"). |
| `slug` | `text` | Slug único dentro do clube para navegação na URL: `/clubes/[slug]/canais/[channelSlug]`. |
| `description` | `text` | Finalidade do canal e orientações editoriais aos leitores. |
| `kind` | `text` | Tipo semântico: `general`, `spoiler`, `chapter`, `announcement`. |
| `is_spoiler` | `boolean` | Flag que ativa a barreira de consentimento para o usuário. |
| `chapter_id` | `uuid` | Associação opcional a um capítulo específico da obra. |
| `created_at` | `timestamptz` | Data de criação do canal. |

## 4. Mensageria em Tempo Real & Concorrência Otimista

### 4.1 Envio de Mensagens (`post_club_message`)
O envio de mensagens é mediado pela RPC transacional `post_club_message`:
- **Parâmetros:** `p_channel_id`, `p_content`, `p_parent_id` (opcional), `p_is_spoiler` (opcional), `p_idempotency_key` (opcional).
- **Validações do Servidor:**
  1. O leitor deve ter sessão autenticada (`auth.uid()`).
  2. O canal deve ser acessível via `is_channel_accessible(p_channel_id)`.
  3. O leitor não pode estar sob sanção ativa (`club_member_sanctions`).
  4. Se `p_parent_id` for informado, o pai deve pertencer estritamente ao mesmo canal (`cross_channel_parent_reply_denied`).
  5. Se uma chave de idempotência for reenviada, a mensagem já persistida é retornada sem duplicação.

### 4.2 Edição e Concorrência Otimista (`edit_club_message`)
Para prevenir sobrescrita concorrente quando dois dispositivos ou abas editam a mesma mensagem, a RPC adota versionamento:
```sql
CREATE OR REPLACE FUNCTION public.edit_club_message(
  p_message_id uuid,
  p_new_content text,
  p_expected_version integer
) RETURNS jsonb AS $$
DECLARE
  v_current_version integer;
BEGIN
  SELECT version INTO v_current_version 
  FROM public.club_messages 
  WHERE id = p_message_id AND user_id = (SELECT auth.uid())
  FOR UPDATE;
  
  IF NOT FOUND THEN
    RAISE EXCEPTION 'message_not_found_or_not_owner';
  END IF;
  
  IF v_current_version <> p_expected_version THEN
    RAISE EXCEPTION 'version_mismatch: message was modified concurrently';
  END IF;
  
  UPDATE public.club_messages
  SET content = p_new_content,
      version = version + 1,
      is_edited = true,
      updated_at = now()
  WHERE id = p_message_id;
  
  RETURN jsonb_build_object('success', true, 'version', v_current_version + 1);
END;
$$ LANGUAGE plpgsql SECURITY DEFINER SET search_path = '';
```

## 5. Proteção de Spoilers & Consentimento Explícito

O DIYSpur implementa um sistema de duas camadas para proteger a experiência de leitura:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        CAMADAS DE PROTEÇÃO ANTI-SPOILER                │
├────────────────────────────────────────────────────────────────────────┤
│  Nível 1: No Canal (channel_members_spoiler_consent)                   │
│  - Canais com kind = 'spoiler' ou is_spoiler = true são bloqueados     │
│  - O leitor deve assinar eletronicamente o termo de consentimento      │
│  - O consentimento fica registrado com user_id, channel_id e timestamp│
├────────────────────────────────────────────────────────────────────────┤
│  Nível 2: Na Mensagem Individual (spans com blur visual)               │
│  - Mensagens marcadas como spoiler exibem desfoque css (.spoiler-blur) │
│  - Clique ou toque no texto desfocado destrava a leitura               │
│  - Leitor pode ocultar novamente a qualquer momento                    │
└────────────────────────────────────────────────────────────────────────┘
```

## 6. Moderação de Conteúdo e Sanções

### 6.1 Fila de Denúncias (`content_reports`)
- Qualquer leitor pode denunciar mensagens com violação de conduta através do componente `ReportButton`.
- **Limiar de Auto-Ocultação:** Se uma mensagem atingir 3 denúncias de usuários distintos, o banco ativa temporariamente `is_hidden = true` até a deliberação dos moderadores.
- **Console Administrativo (`/admin/moderation`):**
  - Moderadores e administradores visualizam o contexto da denúncia.
  - Ações disponíveis: *Ocultar Conteúdo*, *Resolver Denúncia* (aceitar), *Dispensar Denúncia* (falso positivo).

### 6.2 Sanções e Suspensões (`club_member_sanctions`)
- Gestores de clubes podem aplicar advertências, suspensões temporárias ou banimento permanente.
- A função de segurança `check_member_active_sanctions` é consultada antes de qualquer inserção de mensagem ou reação, bloqueando usuários sancionados com a mensagem `user_is_banned_from_club`.
