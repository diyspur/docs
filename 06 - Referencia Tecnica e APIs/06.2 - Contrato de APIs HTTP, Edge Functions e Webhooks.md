## 1. Visão Geral da Superfície de APIs

O ecossistema DIYSpur expõe endpoints organizados em dois planos de execução:
1. **Next.js API Routes (Borda Vercel / Node.js Runtime):** Handlers responsáveis por sessões web, downloads de arquivos (.ics), exportações LGPD e redirecionamentos seguros de afiliados.
2. **Supabase Edge Functions (Deno Runtime):** Funções distribuídas para validação pedagógica de quizzes, distribuição de XP, webhooks de pagamento (Stripe), computação de IA/embeddings e workers de mensageria.

## 2. Rotas de API HTTP no Next.js (App Router)

### 2.1 `/api/notifications`
- **Método:** `GET`
- **Autenticação:** Sessão de usuário obrigatória via cookies `@supabase/ssr`.
- **Query Params:**
  - `limit` (opcional, padrão 20): Quantidade máxima de registros.
  - `offset` (opcional, padrão 0): Deslocamento de paginação.
  - `channel` (opcional): Filtro por canal semântico (`discussions`, `editorial`, `events`, `gamification`).
  - `unread_only` (opcional, booleano): Se `true`, retorna apenas não lidas.
- **Resposta Sucesso (200 OK):**
  ```json
  {
    "notifications": [
      {
        "id": "a1b2c3d4-...",
        "kind": "club_message_mention",
        "title": "Nova menção no clube",
        "body": "@leitor mencionou você no canal #geral",
        "href": "/clubes/clube-verity/canais/geral",
        "read_at": null,
        "created_at": "2026-10-17T18:00:00.000Z"
      }
    ],
    "unreadCount": 3
  }
  ```

---

### 2.2 `/api/account/export`
- **Método:** `GET`
- **Autenticação:** Usuário autenticado.
- **Finalidade:** Conformidade com o Artigo 18 da LGPD (Portabilidade de Dados).
- **Cabeçalhos:**
  - `Content-Type: application/json`
  - `Content-Disposition: attachment; filename="diyspur-meus-dados-[userId].json"`
- **Payload Exportado:** Dossiê completo incluindo dados cadastrais, leituras canônicas, notas do diário, participações em clubes, mensagens postadas, consentimentos de spoilers e histórico de quizzes.

---

### 2.3 `/api/ics/[meetingId]`
- **Método:** `GET`
- **Autenticação:** Pública para encontros de clubes abertos; autenticada para clubes privados.
- **Finalidade:** Download de arquivo iCalendar em conformidade estrita com a norma **RFC 5545**.
- **Cabeçalhos:**
  - `Content-Type: text/calendar; charset=utf-8`
  - `Content-Disposition: attachment; filename="encontro-[slug].ics"`
- **Regras RFC 5545:** Dobra de linhas em 75 octetos com CRLF + espaço (`\r\n `), escape de caracteres especiais e carimbos UTC.

---

### 2.4 `/api/affiliate/[slug]`
- **Método:** `GET`
- **Finalidade:** Rastreamento anônimo de intenção de compra e redirecionamento seguro para a Amazon.
- **Segurança:** O IP do leitor nunca é gravado em texto claro; calcula-se apenas o hash unidirecional `ip_hash` com salt para prevenção de fraudes. Responde com `307 Temporary Redirect` para a URL comissionada canônica.

---

### 2.5 `/api/health`
- **Método:** `GET`
- **Finalidade:** Verificação de integridade operacional do sistema para monitoramento contínuo.
- **Resposta Sucesso (200 OK):**
  ```json
  {
    "status": "healthy",
    "timestamp": "2026-10-17T20:24:00.000Z",
    "database": {
      "connected": true,
      "latency_ms": 14
    },
    "version": "1.0.0"
  }
  ```

## 3. Rotas de API HTTP no Console Administrativo (`diyspur/admin`)

O repositório independente [diyspur/admin](https://github.com/diyspur/admin) disponibiliza endpoints dedicados à automação de acesso e governança operacional:

### 3.1 `/api/auth/auto-login`
- **Método:** `POST`
- **Finalidade:** Emissão de credenciais e persistência de sessão para operadores do console administrativo.
- **Mecanismo:**
  1. Valida flag `NEXT_PUBLIC_ADMIN_DEV_AUTH` e credenciais padrão (`ADMIN_DEFAULT_EMAIL`, `ADMIN_DEFAULT_PASSWORD`).
  2. Executa autenticação via Supabase Auth (`signInWithPassword`). Em ambiente local/dev onde o Supabase Auth ainda não possui o usuário criado, aplica fallback de dev-session proxy para não bloquear a operação.
  3. Define o cookie de sessão seguro `diyspur_admin_session` (`HttpOnly`, `Path=/`, `SameSite=Lax`, expiração de 7 dias).
- **Resposta Sucesso (200 OK):**
  ```json
  {
    "success": true,
    "user": {
      "email": "admin@diyspur.com",
      "role": "admin"
    },
    "redirectTo": "/admin"
  }
  ```

---

### 3.2 `/api/auth/create-admin`
- **Método:** `POST`
- **Finalidade:** Provisionamento automático da conta administrativa no Supabase Auth (`auth.users`) utilizando a `SUPABASE_SERVICE_ROLE_KEY`.
- **Mecanismo:**
  1. Invoca a API administrativa do Supabase (`supabase.auth.admin.createUser`).
  2. Garante `email_confirm: true` e atribui metadados `app_metadata: { role: 'admin' }`.
  3. Caso o usuário já exista, realiza a reconciliação e atualização de senha (`updateUserById`).
- **Resposta Sucesso (200 OK):**
  ```json
  {
    "success": true,
    "message": "Conta administrativa configurada com sucesso.",
    "email": "admin@diyspur.com"
  }
  ```

## 4. Matriz de Contratos das 11 Edge Functions (Deno)

| Edge Function | Gateway `verify_jwt` | Protocolo de Autenticação | Finalidade Operacional |
|---|---|---|---|
| `quiz-validate` | `true` | JWT do usuário logado via Bearer. | Confere gabarito no schema `private`, calcula score pedagógico e grava tentativa atômica. |
| `award-xp` | `true` | JWT do usuário ou service-role. | Atribui experiência por tarefas cumpridas, garantindo idempotência com chave única. |
| `vote-next-book` | `true` | JWT do usuário logado. | Registra voto em enquete aberta, impedindo votos múltiplos para a mesma temporada. |
| `scheduled-reminders` | `false` | Header `x-scheduled-reminders-secret`. | Invocado por cron job para calcular e despachar lembretes de encontros com antecedência de 24h e 1h. |
| `community-notification-worker` | `false` | Secret de serviço ou token de cron. | Drena itens da fila `notification_outbox` usando `FOR UPDATE SKIP LOCKED` e efetua disparos. |
| `ai-recommendations` | `true` | JWT do usuário logado. | Calcula sugestões personalizadas de livros a partir de similaridade por cosseno no `pgvector`. |
| `ai-user-embeddings` | `true` | JWT do usuário logado. | Gera o vetor semântico de preferências do leitor a partir do histórico de resenhas e moods. |
| `match-readers` | `true` | JWT do usuário logado. | Identifica outros leitores da comunidade com alta afinidade literária (*Reader Match*). |
| `newsletter-dispatch` | `true` | JWT com validação de papel `role = 'admin'`. | Dispara edições da newsletter editorial para assinantes confirmados via API do Resend. |
| `stripe-webhook` | `false` | Header `stripe-signature` com HMAC. | Processa eventos de assinatura e pagamentos com verificação criptográfica do corpo bruto. |
| `social-render-card` | `true` | JWT do usuário logado. | Gera cartões visuais para Instagram Stories e TikTok com metadados do leitor e capa do livro. |
